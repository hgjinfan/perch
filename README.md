# 栖页 · Perch

安放服务与日常的个人首页。为 VPS 自托管设计，紧凑磁贴布局、雾白/石墨主题、RSS/Atom、天气、服务可用性、书签和项目入口。前端不依赖框架，不需要构建；Node.js 负责数据获取、缓存和 HTML 模板渲染，浏览器只负责局部更新与交互。

## 本地启动

需要 Node.js 22 或更新版本。当前版本 **v0.1.0**，采用 [MIT 许可证](LICENSE)。

```sh
git clone https://github.com/hgjinfan/perch.git
cd perch
npm ci
cp .env.example .env
npm start
```

访问 http://127.0.0.1:3210 。`.env` 中管理员密码默认留空，管理入口保持关闭；启用前请设置自己的强密码。开发时可使用 `npm run dev`，修改服务端文件自动重启。

## 换成自己的内容

编辑根目录的 `config.json`，重启服务生效：

- `title`：左上角名称。
- `timezone`：日期时区，示例使用 `UTC`。
- `services`：磁贴入口。填写 `url` 后可以点击并自动检测；未配置时明确显示“待配置”。`icon` 使用 Lucide 图标名。可选 `healthUrl` 指向独立健康检查地址，该地址不会发送到浏览器。
- `feeds`：支持 RSS 2.0、RSS 1.0 与 Atom。`url` 是订阅地址，`site` 是访问源站的地址，`limit` 是条目数量（1–20）。`id` 必须唯一。
- `weather`：城市名称、经纬度及当地时区。初始城市为示例固定城市 London；可设为 `null` 禁用数据获取。
- `bookmarks` / `projects`：名称与网址。

服务和博客地址由部署者自行配置，示例保留空值；没有虚构在线状态或博客文章。服务列表完全可增删。Docker 磁贴应该填管理页面地址，不应填 Docker daemon API。

公开首页提供内容浏览和主题切换，主题偏好保存在访问者自己的浏览器。模块显隐、排列和内容配置由管理员统一管理；旧版本浏览器里的模块设置不再生效。隐藏模块在服务端也会停止公开其配置和数据接口。

## VPS 部署

```sh
docker compose up -d --build
```

默认仅将容器端口绑定到 VPS 的 `127.0.0.1:3210`，用现有 Nginx 或 Caddy 反向代理域名。例如 Caddy：

```caddy
home.example.com {
    reverse_proxy 127.0.0.1:3210
}
```

切换域名前先备份现有反向代理配置并确认预览。配置文件以只读方式挂载，修改后运行 `docker compose restart`。容器以非 root 用户运行，文件系统只读。

首页内容公开，管理页面和写入接口使用 HTTP Basic 管理员认证。正式部署必须通过 HTTPS 反向代理访问；不要在公开链接中填写账号密码或令牌。

## 数据行为

- 首页每分钟检查更新；后台 RSS 缓存 5 分钟，天气 15 分钟，状态 1 分钟。返回页面时自动检查到期任务，恢复联网时重新获取内容；请求遵循服务端缓存，防止频繁请求上游。
- 一个订阅源失败不会阻塞其他模块；已有内容会保留并标明缓存状态。首次失败会显示错误和重试入口。
- 服务检测使用 GET，5 秒超时。2xx 表示可访问；401/403 表示服务可到达但需要权限，不代表登录后的业务正常；其他状态显示 HTTP 异常。
- 状态只代表 HTTP 可达性，不代表容器健康或完整业务健康。
- 资讯链接仅允许 HTTP(S)，标题作为纯文本渲染。XML 响应限 1 MiB，禁止 DTD/实体声明。
- 天气使用 Open-Meteo，保留页面署名；适用范围与限额请参考其服务条款。

## 检查

```sh
npm run check
npm test
```

环境变量：`HOST`（默认 `127.0.0.1`）、`PORT`（默认 `3210`）、`CONFIG_PATH`（可选其他配置文件路径）。`/healthz` 提供进程健康检查。

## 管理员与访客

- `/`：公开首页，只有浏览和主题切换。
- `/admin`：浏览器弹出管理员登录框，登录后可以编辑首页名称、密度、模块显隐、服务、订阅、天气、书签和项目。
- `/api/admin/config`：读取和写入均需服务端认证，写入另校验同源 Origin 和 JSON 类型；错误登录达到限制后暂停十分钟。
- 未设置 `ADMIN_PASSWORD` 时返回 503，管理入口关闭，没有默认密码。

启用方式：在服务器环境或项目根目录 `.env` 中设置 `ADMIN_USERNAME`（默认 admin）和 `ADMIN_PASSWORD` 后重启。`npm start` 和 Docker Compose 均支持未提交的 `.env` 文件，已有进程环境变量优先。不要把密码写入前端或 config.json。HTTP Basic 凭据会由浏览器暂存；共享电脑请使用独立浏览器会话，使用结束后关闭会话。

管理员保存后自动生效并持久化至 `data/site.json`（可通过 `STATE_PATH` 指定路径）。Docker 使用 `homepage-data` 卷保存此文件，重建容器不会丢失。存在保存的配置时它优先于 config.json；config.json 作为初始配置。已打开首页会检查配置变化并提示刷新，点击后读取新配置。保存操作使用临时文件与原子替换。

## 磁块内容配置

管理页现在支持修改内置磁块标题，以及新增自定义磁块。旧配置自动兼容，未指定 `widgets` 时按空列表处理。

### 展示模板

- 文本：纯文本，保留换行；不执行 HTML 或脚本，当前不解析 Markdown。
- 链接集合：标题和跳转地址，非法协议不生成可点击链接。
- 单值指标：数字、单位、小数位数。
- 多值指标：最多 8 个指标，各自设置名称、字段路径和单位。
- 内容列表：标题、说明、可选链接，显示 1–20 条。
- 进度条：已用值、总量、单位和百分比告警阈值。

服务磁贴与订阅通过名称修改标题；天气、书签、关注项目通过“磁块标题”修改。服务状态已合并进顶部入口，不再有独立标题。`titles` 保存内置模块标题，`widgets` 保存自定义模块。

### 数据源和字段映射

支持手动数据和 JSON API。API 可配置 GET/POST、查询参数（放在 URL 中）、请求头、JSON 正文和 30–86400 秒刷新间隔。POST 只应配置用于读取数据的查询接口，因为刷新会重复调用。页面可见时按间隔获取数据；服务器按相同间隔缓存并合并并发请求。刷新间隔以 5 秒为检查粒度。自动更新及模块重试仍遵循服务器缓存。

字段路径使用 `data.balance`、`data.items`、`data.0.value`；空路径表示整个响应。列表条目字段相对于每个条目。只支持属性路径，不支持 JavaScript、计算表达式或任意模板代码。数值缺失和类型错误会显示失败，不会假装为 0。

“测试数据并预览”读取当前未保存的配置并返回实际展示结果；只有管理员能调用。预览不会保存配置，API 测试会执行配置的请求。保存后新磁块才出现在公开首页。示例见 `widget-examples.json`，里面的示例域名需替换，未自动启用这些示例。

### 接口认证

请求由服务器发送，公开配置不包含接口地址、请求头、正文或字段映射，数据接口只返回映射后的内容。管理员可使用请求头，例如：

```json
{ "Authorization": "Bearer ${WIDGET_TRAFFIC_TOKEN}" }
```

将 `WIDGET_TRAFFIC_TOKEN` 作为服务器环境变量提供。只有 `WIDGET_` 前缀的变量可在请求头中引用。Docker Compose 需在 `environment` 中显式传入需要的变量，例如 `WIDGET_TRAFFIC_TOKEN: ${WIDGET_TRAFFIC_TOKEN}`；只写到 Compose 的 `.env` 不会自动注入容器。

API 请求超时 8 秒、响应最多 1 MiB，不跟随重定向，避免认证头被转发到其他地址。失败时保留上次成功的展示数据并标明更新时间；首次失败显示重试入口。隐藏的订阅、自定义磁块、天气和状态模块数据接口返回 404。选中的展示字段会公开，请勿把密钥字段作为展示数值或文本。认证信息若直接写入请求头，会保存在服务器的管理配置中；推荐使用环境变量引用。

## PWA 安装与离线

首页提供应用清单、192/512 像素图标、maskable 图标及 Apple Touch 图标，可以在支持的浏览器中安装为独立窗口。浏览器触发安装事件后，首页右上角出现安装入口；iPhone/iPad 的入口提示通过 Safari 分享菜单“添加到主屏幕”。正式域名需要 HTTPS；本机 localhost/127.0.0.1 可用于开发验证。是否显示安装提示由浏览器和平台决定。

- Service Worker 仅缓存通用离线页、样式、脚本和图标。服务端生成的首页 HTML、磁块片段、管理员页面、管理脚本、API、认证请求及带查询参数的地址不进入离线缓存。
- 断网后可重新打开应用界面；数据需要联网，已有页面上的内容仅供参考。恢复网络后自动重新载入或刷新。
- 新版界面文件产生新的内容哈希，浏览器检测到新版本后显示“更新应用”。用户点击后才激活并刷新页面，避免使用中途自动切换。
- 此版没有离线编辑、数据持久化或推送通知。后台仅在页面可见且联网时轮询。
- `src/pwa.js` 生成界面资源清单及版本号；`public/sw.js` 实现缓存；`public/pwa/client.js` 管理安装、联网状态和更新 UI。
- 修改界面后重启服务以重新生成缓存版本。图标可通过 `python3 scripts/generate-icons.py` 重新生成。

参考：[MDN PWA 安装指南](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。

## 访客所在地天气

天气支持 `mode: "ip"` 和 `mode: "fixed"`。默认使用示例固定城市；管理员可主动启用按访客 IP 定位，失败回退到配置中的城市；旧配置未设置 mode 时保持固定城市。管理页可以修改位置模式和默认城市。IP 定位由服务端调用 `https://ipwho.is/{访客IP}` 完成，IP 会发送给该服务，但不返回给前端、不写入配置或磁盘。地理结果在内存缓存 6 小时（最多 512 项），天气按坐标与时区隔离缓存 15 分钟（最多 256 项）。定位供应商可能限流，发生错误时自动回退。VPN/代理出口可能影响定位结果。

首页天气块提供“切换城市”：搜索城市后只保存在当前浏览器，不改变其他访客的天气。选择“恢复默认位置”清除个人选择，恢复管理员指定的自动或固定模式。城市搜索使用 Open-Meteo Geocoding API。

### 反向代理设置

默认 `TRUST_PROXY_HOPS=0`，使用连接来源 IP，忽略所有转发头。VPS 在单层 Nginx/Caddy 之后部署时设置 `TRUST_PROXY_HOPS=1`，并保证应用端口只接受该反向代理的连接。服务从 `X-Forwarded-For` 的右侧按固定层数取地址，避免相信可伪造的最左侧内容；本地、内网、无效地址不会用于公网定位。

Nginx 单层代理示例（替换现有 location 内的对应设置）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3210;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Compose 的 `.env` 设置 `TRUST_PROXY_HOPS=1` 后重新创建容器。若有 CDN 或多层代理，需要按实际可信链配置；不要直接将不可信转发头当作访客地址。本机 `127.0.0.1` 预览显示默认城市是正常行为，不会通过查询服务器出口 IP 假装访客定位成功。

参考：[IP 定位接口文档](https://ipwhois.io/documentation)、[城市搜索文档](https://open-meteo.com/en/docs/geocoding-api)。

## 加载与刷新体验

首次响应直接包含服务端生成的服务入口、模块标题和内容骨架，无需浏览器读取配置或组装布局。资讯按配置条数预留列表行，天气、指标、进度条和链接各有对应形状，保持自然高度。未配置的模块直接显示空状态。

每个模块独立标记加载状态。刷新时保留已有内容并在标题旁显示“更新中”；首次加载失败退出骨架并提供重试，已有内容更新失败时保留上次结果。骨架使用静态色块，不引入闪烁或循环动画。骨架由 `src/render/skeleton.js` 生成，客户端加载状态由 `public/home/loading.js` 处理。模板骨架是估计高度，实际内容行数或文字长度变化仍可能引起少量重排。

## 服务端 HTML 渲染与配置边界

- `GET /`：直接返回包含可见磁块框架、标题、服务入口、书签和骨架的完整 HTML。响应不等待上游数据。
- `GET /fragments/feed-<id>`、`/fragments/widget-<id>`、`/fragments/weather`、`/fragments/status`：返回服务端渲染的 HTML 片段，独立加载与刷新。
- `GET /fragments/weather/cities?q=...`：返回城市选择按钮的 HTML；手动选择的位置只保存在当前浏览器。
- `/api/config` 和旧的公开 JSON 数据接口已移除，返回 404。浏览器不再获取布局配置、磁块类型或数据映射来生成页面。
- `/api/admin/config` 保留需认证的 JSON 读写；`POST /api/admin/widget-preview` 接受管理配置，返回与正式展示共用模板生成的 HTML。

上游地址、认证头、密钥变量、字段映射、健康检查地址和默认天气坐标只在服务端使用。HTML 属性只携带局部更新所需的模块标识、片段地址和刷新间隔。隐藏模块不渲染、片段接口返回 404；在请求等待期间隐藏模块也不会返回其内容。所有标题、文本和属性均做 HTML 转义，链接仅允许 HTTP(S)。

服务入口、书签和文章链接仍是公开内容，访客可以查看目的地。将某个字段映射到磁块展示即意味着公开它；返回 HTML 并不改变已展示内容的可见性。

服务端模板在 `src/render/`；客户端 `public/home/loaders.js` 只替换内容区域。选城控件和输入框留在区域之外，局部更新不会重建它们。PWA 网络导航请求获取最新服务端页面，断网显示通用离线页，恢复联网后重新访问首页。已有安装若提示“更新应用”，点击后加载本次渲染架构版本。

### 未来 12 小时预报

天气磁块显示当前位置从下一整点开始、未来 12 小时内的逐小时温度，共最多 12 个时段。细柱高度展示这段时间的温度变化，温度数值与详情保留真实单位；鼠标悬停、点击或聚焦时显示该小时的温度、天气和降水概率，跨午夜标注“明日”。左右方向键及 Home/End 可以切换时段。触屏提供横向滚动和足够大的点选区域。

小时数据与 HTML 都在服务端获取、渲染，浏览器只处理选中状态。自动更新保留选中的时间点，已经过去的时间点会回退到最新一小时。上游缺失天气或降水字段时不编造数值。

### 服务入口与状态合并

顶部服务磁贴同时显示名称、访问入口和状态：在线时显示延迟，异常时显示 HTTP 状态码或“无法连接”；悬停或聚焦入口可查看说明。未配置访问地址时在名称下显示“待配置”，不生成无法访问的链接。

内容区不再创建独立的服务状态卡片。`/fragments/status` 返回顶部状态槽位的 HTML，自动更新只替换状态，不重建链接或图标。更新失败保留上次状态并提供重试，提示在服务区下方，避免占用磁贴位置。管理页“服务入口状态”可统一关闭此功能，兼容旧 `layout.hidden` 中的 `status` 标识；旧 `titles.status` 仍可读取但不再用于展示。

## 发布与编辑可靠性

静态资源及完整模块依赖图使用发布哈希地址；公开资源支持 ETag / 304，版本资源可长期缓存，管理资源始终 no-store。首页与动态片段不离线缓存。旧页面请求旧版或无版本片段时返回更新提示，需重新加载。静态资源在启动时建立内存快照，修改后重启服务生效。

管理配置 GET 返回 ETag，PUT 必须携带 If-Match；缺少版本返回 428，版本冲突返回 409，保留当前表单以便对照最新配置。预览在继续编辑时自动失效。

天气响应校验关键温度与小时结构，失败时保留可用旧数据。天气和城市搜索按可信访客地址限流；登录限流也复用 TRUST_PROXY_HOPS 信任规则。可选环境变量：

| 变量                   | 默认值 | 范围 / 用途                 |
| ---------------------- | ------ | --------------------------- |
| WEATHER_RATE_LIMIT     | 60     | 每访客每分钟天气请求，1–600 |
| CITY_SEARCH_RATE_LIMIT | 20     | 每访客每分钟城市搜索，1–120 |
| WEATHER_CONCURRENCY    | 4      | 天气相关上游并发，1–16      |

上游最多排队 12 个请求、等待 2 秒；供应商限流或连续失败时暂停请求 30 秒。预算拒绝返回 Retry-After。

## 磁贴排序与分组

管理页“磁贴布局”支持最多 12 个内容分组，名称留空时不显示标题；每组独立设置 1–4 列。磁块可通过拖动手柄排序或跨组移动，也可使用上移/下移按钮及“分组”选择器操作。每个磁块可设置 1–4 列宽度，高度始终由内容决定。宽度超过组列数时按组宽显示，平板最多 2 列、手机 1 列。

布局以从左到右、从上到下的顺序排列；高度变化时自动调整占位，保留阅读及键盘顺序。为保持明确顺序，不使用会把后面的磁块提前填入空隙的 dense 重排。移除分组会将其内容移入保留的分组，不会删除磁块；新增内容自动补入首组。空组或全部隐藏的组不会在公开首页显示。

`layout.groups` 保存 `{ id, title, columns, items: [{ id, span }] }`；磁块 ID 使用 `feed-<id>`、`widget-<id>`、`weather`、`bookmarks`、`projects`。旧配置自动生成默认分组。顶部服务入口保持独立，可在“服务入口”中用按钮调整顺序；服务状态仍与入口合并。书签及项目内部条目也可排序。保存后刷新公开首页读取新布局。

## 配置备份与恢复

管理员在管理页底部“配置备份与恢复”下载当前**已保存配置**。文件包含首页内容、分组、跨列宽度、显隐、服务入口和自定义接口配置，不包含当前表单未保存的编辑、`.env`、管理员密码、运行缓存或历史快照。直接写入请求头的令牌属于配置，会随 JSON 导出；环境变量引用保留为引用，迁移时需单独提供对应 `.env`。备份文件未加密，请妥善保存。

恢复支持本应用生成的版本化备份文件，也兼容旧的原始配置 JSON，最大 1 MiB。选择文件后先在服务端校验并展示名称与各类内容数量；这一步不会保存、调用数据源或修改配置。勾选确认并点击恢复后，整份配置会被替换（不做合并），当前未保存编辑将清除。成功后管理页重新加载，公开首页刷新后读取恢复结果。

每次恢复前，服务器先把当前已保存配置写入状态文件同目录的 `backups/`，默认即 `data/backups/`，保留最近 10 份恢复前快照，可检查恢复或下载。快照保存失败会阻止恢复；配置写入失败保留运行中的配置和已创建的快照。Docker 使用现有数据卷持久化这些文件，无需增加挂载。普通“保存并应用”不会创建历史快照，可按需手动下载备份。

备份读写只对管理员开放，恢复继续校验同源请求和配置 ETag；文件检查后若其他页面已保存修改，恢复会拒绝，需重新检查。当前存储按单进程服务设计，请勿让多个应用实例共享同一状态文件。备份不代替整机或异地备份，迁移仍需保管服务器环境变量。

## 常用数据源预设

管理页“自定义磁块 → 从常用数据源添加”提供 6 个预设。填写服务地址、仓库或监控标识后添加为新磁块，自动生成 GET 接口、认证头引用、展示模板、字段映射、单位和刷新间隔。添加本身不请求数据、不保存，也不覆盖已有磁块；继续使用“测试数据并预览”确认实际接口结果，最后保存。生成后是普通自定义磁块，可以编辑、分组、排序、备份和恢复，不依赖运行时插件。

| 预设        | 展示内容                            | 填写内容与边界                                                                                   | 接口依据                                                                        |
| ----------- | ----------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| GitHub      | Stars、Forks、未关闭 Issues/PR 合计 | 所有者与仓库名；公开仓库可免认证，私有数据使用 Token                                             | [官方仓库 API](https://docs.github.com/en/rest/repos/repos#get-a-repository)    |
| Gitea       | Stars、Forks、未关闭 Issues         | 站点地址、所有者、仓库名；私有仓库需读取权限 Token                                               | [官方仓库 API](https://docs.gitea.com/api/operations/repo-get/)                 |
| Immich      | 照片数、视频数、占用 GiB            | 站点地址；管理员 API Key 需 server.statistics 权限                                               | [官方统计 API](https://api.immich.app/endpoints/server/getServerStatistics)     |
| Uptime Kuma | 指定监控的 24 小时可用率            | 已发布状态页 slug、监控 ID；使用公开 JSON 接口，版本升级可能改变内部接口                         | [项目 API 说明](https://github.com/louislam/uptime-kuma/wiki/API-Documentation) |
| Nezha 新版  | 服务器名称、ID 清单                 | `/api/v1/server` 返回 `success/data` 的面板，Bearer Token；PAT 需 inventory:read。非实时资源监控 | [新版接口说明](https://nezha.wiki/en_US/guide/api)                              |
| Nezha 旧版  | 指定服务器 CPU%、已用内存/磁盘 GiB  | `/api/v1/server/details?id=...` 返回 `result` 与 `status.CPU` 的旧面板，原始 Authorization Token | [旧版接口说明](https://nezha-v0.mereith.dev/guide/api)                          |

站点地址填写站点根路径（可以带反向代理前缀），不要重复附加 `/api`。版本不同不自动猜测接口，若预览失败请按实际服务文档调整生成的普通磁块。没有为 Docker daemon、Vaultwarden 管理端等假造通用统计 API。

预设认证仅要求**环境变量名**，默认如 `WIDGET_IMMICH_TOKEN`；实际密钥在服务器 `.env` 设置，Docker Compose 还需在 environment 中显式传入。GitHub/Gitea 可以选择免认证或环境变量 Token。公开内容仍由服务端生成，接口地址、请求头、字段映射及密钥不发送给访客；选择展示的数据本身是公开内容。

数值展示新增可选 `scale` 倍率：单值指标设置 `scale`，多值指标在各个 fields 中设置。先读取数值再乘倍率，最后按小数位格式化；例如 0–1 比例乘 100 转为百分比，字节乘 `1/1073741824` 转为 GiB。不执行表达式或脚本，倍率必须为有限正数，范围 1e-12–1e12；旧配置未设置时沿用 1。进度条继续按原始已用量/总量计算，不使用倍率。

## 管理页编辑体验

底部固定操作栏显示“有未保存的修改 / 正在保存 / 所有修改已保存”，可随时保存或放弃修改。只有内容、布局或编辑字段真的变化时才标记未保存，预设填写、备份文件选择和预览结果本身不算首页配置修改。离开或刷新有未保存内容的页面时，浏览器会提示；浏览器是否显示提示取决于平台及用户交互条件。草稿只保留在当前页面内存，不写浏览器存储，以免持久化接口密钥。

保存前检查字段，并自动展开、滚动和聚焦第一处错误；JSON 格式、请求头结构、字段路径、时区、必填项及数值范围都有就近提示。服务端仍重新校验全部配置，冲突或请求失败时保留编辑。保存过程中编辑区暂时锁定，避免返回结果覆盖新输入。

自定义磁块支持复制：生成新 ID，深拷贝内容、映射和接口设置，副本紧跟原磁块所在分组、继承宽度及显隐。仍计入最多 20 个磁块。复制前需修正该磁块中的字段错误，不执行上游请求。添加、删除或复制导致表单重绘时，错误 JSON 文本与磁块展开状态会保留；切换模板/数据源按对应编辑上下文保存错误文本。成功保存、明确放弃或恢复备份后重新建立编辑基准。

### 宽度与跨列预览

磁贴布局的“宽度”除 1–4 列外，也支持“整行”。整数宽度超过当前可见列数时自动收缩；“整行”始终铺满所在分组，改变分组列数或屏幕宽度后仍保持铺满。高度仍随内容变化，不增加固定行高设置。

分组上方提供桌面 / 平板 / 手机宽度示意，分别使用分组设定列数、最多 2 列、1 列。隐藏磁块不出现在示意中，点击示意磁块可定位其宽度设置。示意只展示宽度及顺序，不模拟实际内容高度；切换预览不会改变配置或产生未保存标记。

配置项 `layout.groups[].items[].span` 接受 1–4 整数或字符串 `"full"`；已有整数配置保持兼容，复制磁块、备份和恢复沿用该值。保存后刷新公开首页生效。

## 配置更新提示

已打开的公开首页在可见且联网时约每 30 秒检查一次页面版本；返回页面或恢复联网时额外检查，并对短时间重复触发做合并与节流。同一浏览器中，管理页保存或恢复成功会通过 BroadcastChannel 通知首页尽快检查；不支持该能力时仍有定期检查。

发现变化后显示“首页配置已更新 / 刷新查看”，不会自动刷新或突然重排布局；点击后重新读取服务端首页。界面资源版本变化会显示“首页已有新版本”。提示与 PWA 的“更新应用”入口、离线提示分别管理。检测失败保持安静，下次继续，不影响磁块数据更新。

`HEAD /page-version` 只返回版本 ETag 与 204/304，无配置正文，使用 no-store，不进入 PWA 缓存。版本标记是随机不透明值，不使用管理员配置摘要；配置内容不变的重复保存不产生新标记。服务重启会重新生成标记，已打开页面也可能收到刷新提示。此接口不抓取上游，不返回接口地址、字段映射、密钥或管理员配置。

## 项目命名

项目名 Perch，中文名“栖页”，介绍为“安放服务与日常的个人首页”。应用清单、管理页、离线页和图标使用同一标识；首页名称仍可由管理员修改。旧 Kyrie 备份可继续导入，既有主题、选城存储键及跨标签通知频道保留用于兼容，Service Worker 激活时清理旧前缀缓存。应用 id、start_url、配置文件路径及数据卷不变。
