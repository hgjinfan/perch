# 栖页 · Perch

安放服务与日常的个人首页。为 VPS 自托管设计，紧凑磁贴布局、雾白/石墨主题、RSS/Atom、天气、服务可用性、书签和项目入口。前端不依赖框架，生产资源使用 esbuild 构建；Node.js 负责数据获取、缓存和 HTML 模板渲染，浏览器只负责局部更新与交互。

设计资料：[项目设计规范](DESIGN.md) · [当前 UI 检查与微调建议](UI-REVIEW.md)。

## 本地启动

需要 Node.js 22 或更新版本。当前版本 **v0.1.7**，采用 [MIT 许可证](LICENSE)。

```sh
git clone https://github.com/hgjinfan/perch.git
cd perch
npm ci
cp .env.example .env
npm start
```

访问 http://127.0.0.1:3210 。`.env` 中管理员密码默认留空，管理入口保持关闭；启用前请设置自己的强密码。`npm start` 会先构建客户端再启动。开发时可使用 `npm run dev`，直接加载原生模块，修改服务端文件自动重启。

生产部署可先执行 `npm ci && npm run build`，再仅安装生产依赖；保留 `dist/client/`、`src/`、`shared/`、`scripts/` 和配置文件即可运行。只有生产依赖时，`npm start` 使用已有构建产物。Docker 多阶段构建会自动完成这些步骤。

## 换成自己的内容

编辑根目录的 `config.json`，重启服务生效：

- `title`：左上角名称。
- `timezone`：日期时区，示例使用 `UTC`。
- `services`：磁贴入口。填写 `url` 后可以点击并自动检测；未配置时明确显示“待配置”。`icon` 使用 Lucide 图标名。可选 `healthUrl` 指向独立健康检查地址，该地址不会发送到浏览器。
- `feeds`：支持 RSS 2.0、RSS 1.0 与 Atom。`url` 是订阅地址，`site` 是访问源站的地址，`limit` 是条目数量（1–20）。`id` 必须唯一。
- `weather`：城市名称、经纬度及当地时区。初始城市为示例固定城市 London；可设为 `null` 禁用数据获取。
- `bookmarks` / `projects`：名称与网址。

服务和博客地址由部署者自行配置，示例保留空值；没有虚构在线状态或博客文章。服务列表完全可增删。Docker 磁贴应该填管理页面地址，不应填 Docker daemon API。

公开首页提供内容浏览和主题切换，主题偏好保存在访问者自己的浏览器。模块显隐、排列和内容配置由管理员统一管理；旧版本浏览器里的模块设置不再生效。隐藏模块在服务端也会停止公开其配置和数据接口。

## VPS 部署

```sh
git clone https://github.com/hgjinfan/perch.git
cd perch
cp .env.example .env
# Edit .env and set a strong ADMIN_PASSWORD. For reproducible deployments,
# pin PERCH_VERSION to a release such as v0.1.7 instead of latest.
docker compose pull
docker compose up -d
```

Docker Compose pulls the prebuilt image from `ghcr.io/hgjinfan/perch`; the VPS does not install Node.js or build the project. Each GitHub release publishes multi-architecture (`linux/amd64` and `linux/arm64`) images. To upgrade, update `PERCH_VERSION` in `.env`, then run `docker compose pull && docker compose up -d`. The `homepage-data` volume is preserved. To build from a local checkout instead, run `docker build -t perch:local .`.

The GHCR package must be public for anonymous pulls. After the first image is published, open the repository's **Packages** tab, select `perch`, then choose **Package settings → Change visibility → Public**. Other users can then deploy it without a GitHub token.

Pushing a `v*` tag automatically builds and publishes that tag for both architectures; stable versions also update `latest`. To publish an already existing tag, run **Actions → Publish container image → Run workflow** and enter the tag.

默认仅将容器端口绑定到 VPS 的 `127.0.0.1:3210`，用现有 Nginx 或 Caddy 反向代理域名。例如 Caddy：

```caddy
home.example.com {
    reverse_proxy 127.0.0.1:3210
}
```

切换域名前先备份现有反向代理配置并确认预览。配置文件以只读方式挂载，修改后运行 `docker compose restart`。容器以非 root 用户运行，文件系统只读。

首页内容公开，管理页面和写入接口使用 HTTP Basic 管理员认证。正式部署必须通过 HTTPS 反向代理访问；不要在公开链接中填写账号密码或令牌。

## 数据行为

- 首页每分钟检查更新；后台 RSS 缓存 5 分钟，天气 15 分钟，状态 1 分钟。返回页面时自动检查到期任务，恢复联网时重新获取内容；请求遵循服务端缓存，防止频繁请求上游。
- 一个订阅源失败不会阻塞其他模块；已有内容会保留并标明缓存状态。首次失败会显示错误和重试入口。
- 服务检测使用 GET，5 秒超时。2xx 表示可访问；401/403 表示服务可到达但需要权限，不代表登录后的业务正常；其他状态显示 HTTP 异常。
- 状态只代表 HTTP 可达性，不代表容器健康或完整业务健康。
- 资讯链接仅允许 HTTP(S)，标题作为纯文本渲染。XML 响应限 1 MiB，禁止 DTD/实体声明。
- 天气使用 Open-Meteo，保留页面署名；适用范围与限额请参考其服务条款。

## 管理员与访客

- `/`：公开首页，只有浏览和主题切换。
- `/admin`：浏览器弹出管理员登录框，登录后可以编辑首页名称、密度、模块显隐、服务、订阅、天气、书签和项目。
- `/api/admin/config`：读取和写入均需服务端认证，写入另校验同源 Origin 和 JSON 类型；错误登录达到限制后暂停十分钟。
- 未设置 `ADMIN_PASSWORD` 时返回 503，管理入口关闭，没有默认密码。

启用方式：在服务器环境或项目根目录 `.env` 中设置 `ADMIN_USERNAME`（默认 admin）和 `ADMIN_PASSWORD` 后重启。`npm start` 和 Docker Compose 均支持未提交的 `.env` 文件，已有进程环境变量优先。不要把密码写入前端或 config.json。HTTP Basic 凭据会由浏览器暂存；共享电脑请使用独立浏览器会话，使用结束后关闭会话。

管理员保存后自动生效并持久化至 `data/site.json`（可通过 `STATE_PATH` 指定路径）。Docker 使用 `homepage-data` 卷保存此文件，重建容器不会丢失。存在保存的配置时它优先于 config.json；config.json 作为初始配置。已打开首页会检查配置变化并提示刷新，点击后读取新配置。保存操作使用临时文件与原子替换。

## 磁块内容配置

管理页现在支持修改内置磁块标题，以及新增自定义磁块。旧配置自动兼容，未指定 `widgets` 时按空列表处理。

### 展示模板

- 文本：纯文本，保留换行；不执行 HTML 或脚本，当前不解析 Markdown。
- 链接集合：标题和跳转地址，非法协议不生成可点击链接。
- 单值指标：数字、单位、小数位数。
- 多值指标：最多 8 个指标，各自设置名称、字段路径和单位。
- 内容列表：标题、说明、可选链接，显示 1–20 条。
- 进度条：已用值、总量、单位和百分比告警阈值。

服务磁贴与订阅通过名称修改标题；天气、书签、关注项目通过“磁块标题”修改。服务状态已合并进顶部入口，不再有独立标题。`titles` 保存内置模块标题，`widgets` 保存自定义模块。

### 数据源和字段映射

支持手动数据和 JSON API。API 可配置 GET/POST、查询参数（放在 URL 中）、请求头、JSON 正文和 30–86400 秒刷新间隔。POST 只应配置用于读取数据的查询接口，因为刷新会重复调用。页面可见时按间隔获取数据；服务器按相同间隔缓存并合并并发请求。刷新间隔以 5 秒为检查粒度。自动更新及模块重试仍遵循服务器缓存。

字段路径使用 `data.balance`、`data.items`、`data.0.value`；空路径表示整个响应。列表条目字段相对于每个条目。只支持属性路径，不支持 JavaScript、计算表达式或任意模板代码。数值缺失和类型错误会显示失败，不会假装为 0。

“测试数据并预览”读取当前未保存的配置并返回实际展示结果；只有管理员能调用。预览不会保存配置，API 测试会执行配置的请求。保存后新磁块才出现在公开首页。示例见 `widget-examples.json`，里面的示例域名需替换，未自动启用这些示例。

### 接口认证

请求由服务器发送，公开配置不包含接口地址、请求头、正文或字段映射，数据接口只返回映射后的内容。管理员可使用请求头，例如：

```json
{ "Authorization": "Bearer ${WIDGET_TRAFFIC_TOKEN}" }
```

将 `WIDGET_TRAFFIC_TOKEN` 作为服务器环境变量提供。只有 `WIDGET_` 前缀的变量可在请求头中引用。Docker Compose 需在 `environment` 中显式传入需要的变量，例如 `WIDGET_TRAFFIC_TOKEN: ${WIDGET_TRAFFIC_TOKEN}`；只写到 Compose 的 `.env` 不会自动注入容器。

API 请求超时 8 秒、响应最多 1 MiB，不跟随重定向，避免认证头被转发到其他地址。失败时保留上次成功的展示数据并标明更新时间；首次失败显示重试入口。隐藏的订阅、自定义磁块、天气和状态模块数据接口返回 404。选中的展示字段会公开，请勿把密钥字段作为展示数值或文本。认证信息若直接写入请求头，会保存在服务器的管理配置中；推荐使用环境变量引用。

## PWA 安装与离线

首页提供应用清单、192/512 像素图标、maskable 图标及 Apple Touch 图标，可以在支持的浏览器中安装为独立窗口。浏览器触发安装事件后，首页右上角出现安装入口；iPhone/iPad 的入口提示通过 Safari 分享菜单“添加到主屏幕”。正式域名需要 HTTPS；本机 localhost/127.0.0.1 可用于开发验证。是否显示安装提示由浏览器和平台决定。

- Service Worker 仅缓存通用启动/离线页、样式、脚本和图标。服务端生成的首页 HTML、磁块片段、管理员页面、管理脚本、API、认证请求及带查询参数的地址不进入离线缓存。
- 断网后可重新打开应用界面；数据需要联网，已有页面上的内容仅供参考。恢复网络后自动重新载入或刷新。
- 新版界面文件产生新的内容哈希，浏览器检测到新版本后显示“更新应用”。用户点击后才激活并刷新页面，避免使用中途自动切换。
- 此版没有离线编辑、数据持久化或推送通知。后台仅在页面可见且联网时轮询。
- `src/pwa.js` 生成界面资源清单及版本号；`public/sw.js` 实现缓存；`public/pwa/client.js` 管理安装、联网状态和更新 UI。
- 修改界面后重启服务以重新生成缓存版本。图标可通过 `python3 scripts/generate-icons.py` 重新生成。

参考：[MDN PWA 安装指南](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。

## 访客所在地天气

天气支持 `mode: "ip"` 和 `mode: "fixed"`。默认使用示例固定城市；管理员可主动启用按访客 IP 定位，失败回退到配置中的城市；旧配置未设置 mode 时保持固定城市。管理页可以修改位置模式和默认城市。IP 定位由服务端调用 `https://ipwho.is/{访客IP}` 完成，IP 会发送给该服务，但不返回给前端、不写入配置或磁盘。地理结果在内存缓存 6 小时（最多 512 项），天气按坐标与时区隔离缓存 15 分钟（最多 256 项）。定位供应商可能限流，发生错误时自动回退。VPN/代理出口可能影响定位结果。

首页天气块提供“切换城市”：搜索城市后只保存在当前浏览器，不改变其他访客的天气。选择“恢复默认位置”清除个人选择，恢复管理员指定的自动或固定模式。城市搜索使用 Open-Meteo Geocoding API。

### 反向代理设置

默认 `TRUST_PROXY_HOPS=0`，使用连接来源 IP，忽略所有转发头。VPS 在单层 Nginx/Caddy 之后部署时设置 `TRUST_PROXY_HOPS=1`，并保证应用端口只接受该反向代理的连接。服务从 `X-Forwarded-For` 的右侧按固定层数取地址，避免相信可伪造的最左侧内容；本地、内网、无效地址不会用于公网定位。

需要将站点挂载在子路径（例如 `https://example.com/perch/`）时，将 `BASE_PATH=/perch` 配置给应用并重启。应用会为页面、管理 API、静态资源、PWA manifest 和 Service Worker 生成带前缀的路径；代理可以保留 `/perch` 转发，也可以在转发时剥掉 `/perch`。子路径只支持由路径段组成的绝对路径，不带末尾斜线，例如 `/apps/perch`。若有代理负责剥除前缀，仍需将 `/perch/sw.js` 映射到应用的 `/sw.js`，并让页面和该脚本经过同一个应用实例。

Nginx 单层代理示例（替换现有 location 内的对应设置）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3210;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Compose 的 `.env` 设置 `TRUST_PROXY_HOPS=1` 后重新创建容器。若有 CDN 或多层代理，需要按实际可信链配置；不要直接将不可信转发头当作访客地址。本机 `127.0.0.1` 预览显示默认城市是正常行为，不会通过查询服务器出口 IP 假装访客定位成功。

参考：[IP 定位接口文档](https://ipwhois.io/documentation)、[城市搜索文档](https://open-meteo.com/en/docs/geocoding-api)。

## 加载与刷新体验

首次响应直接包含服务端生成的服务入口、模块标题和内容骨架，无需浏览器读取配置或组装布局。资讯按配置条数预留列表行，天气、指标、进度条和链接各有对应形状，保持自然高度。未配置的模块直接显示空状态。

每个模块独立标记加载状态。刷新时保留已有内容并在标题旁显示“更新中”；首次加载失败退出骨架并提供重试，已有内容更新失败时保留上次结果。骨架使用静态色块，不引入闪烁或循环动画。骨架由 `src/render/skeleton.js` 生成，客户端加载状态由 `public/home/loading.js` 处理。模板骨架是估计高度，实际内容行数或文字长度变化仍可能引起少量重排。

## 服务端 HTML 渲染与配置边界

- `GET /`：直接返回包含可见磁块框架、标题、服务入口、书签和骨架的完整 HTML。响应不等待上游数据。
- `GET /fragments/<build>/<rev>/feed-<id>`、同前缀的 `widget-<id>`、`weather`、`status`：返回服务端渲染的 HTML 片段，独立加载与刷新。
- `GET /fragments/<build>/<rev>/weather/cities?q=...`：返回城市选择按钮的 HTML；手动选择的位置只保存在当前浏览器。
- `/api/config` 和旧的公开 JSON 数据接口已移除，返回 404。浏览器不再获取布局配置、磁块类型或数据映射来生成页面。
- `/api/admin/config` 保留需认证的 JSON 读写；`POST /api/admin/widget-preview` 接受管理配置，返回与正式展示共用模板生成的 HTML。

上游地址、认证头、密钥变量、字段映射、健康检查地址和默认天气坐标只在服务端使用。HTML 属性只携带局部更新所需的模块标识、片段地址和刷新间隔。隐藏模块不渲染、片段接口返回 404；在请求等待期间隐藏模块也不会返回其内容。所有标题、文本和属性均做 HTML 转义，链接仅允许 HTTP(S)。

服务入口、书签和文章链接仍是公开内容，访客可以查看目的地。将某个字段映射到磁块展示即意味着公开它；返回 HTML 并不改变已展示内容的可见性。

服务端模板在 `src/render/`；客户端 `public/home/loaders.js` 只替换内容区域。选城控件和输入框留在区域之外，局部更新不会重建它们。PWA 导航先显示通用启动界面，再请求最新服务端页面；断网保留连接反馈，恢复联网后自动重试。已有安装若提示“更新应用”，点击后加载本次渲染架构版本。

### 未来 12 小时预报

天气磁块显示当前位置从下一整点开始、未来 12 小时内的逐小时温度，共最多 12 个时段。细柱高度展示这段时间的温度变化，温度数值与详情保留真实单位；鼠标悬停、点击或聚焦时显示该小时的温度、天气和降水概率，跨午夜标注“明日”。左右方向键及 Home/End 可以切换时段。触屏提供横向滚动和足够大的点选区域。

小时数据与 HTML 都在服务端获取、渲染，浏览器只处理选中状态。自动更新保留选中的时间点，已经过去的时间点会回退到最新一小时。上游缺失天气或降水字段时不编造数值。

### 服务入口与状态合并

顶部服务磁贴同时显示名称、访问入口和状态：在线时显示延迟，异常时显示 HTTP 状态码或“无法连接”；悬停或聚焦入口可查看说明。未配置访问地址时在名称下显示“待配置”，不生成无法访问的链接。

内容区不再创建独立的服务状态卡片。`/fragments/status` 返回顶部状态槽位的 HTML，自动更新只替换状态，不重建链接或图标。更新失败保留上次状态并提供重试，提示在服务区下方，避免占用磁贴位置。管理页“服务入口状态”可统一关闭此功能，兼容旧 `layout.hidden` 中的 `status` 标识；旧 `titles.status` 仍可读取但不再用于展示。

## 发布与编辑可靠性

生产 JS/CSS 经压缩、拆包后使用各文件内容哈希地址；首页与管理端分别构建，备份和诊断工具在展开时加载。Lucide 图标在服务端按配置名称渲染为内联 SVG，浏览器不加载图标库；自定义图标和天气片段也使用同一流程，未知图标回退为 box。公开资源支持 ETag / 304，版本资源可长期缓存，管理资源始终 no-store。首页与动态片段不离线缓存。旧页面请求旧配置、旧构建或无版本片段时返回 no-store 的更新提示；配置轮询会重新同步，构建变化需要更新页面。静态资源在启动时建立内存快照，源码修改后需重新构建并重启服务生效。PWA 预缓存核心资源，不再包含图标库分块。`dist/client/report.json` 提供各分块原始大小和 gzip 估算，不通过 HTTP 公开。

管理配置 GET 同时返回 ETag 和独立的 `X-Config-Version`，浏览器优先读取后者，PUT 必须携带 If-Match；缺少版本返回 428，版本冲突返回 409，保留当前表单以便对照最新配置。预览在继续编辑时自动失效。

天气响应校验关键温度与小时结构，失败时保留可用旧数据。天气和城市搜索按可信访客地址限流；登录限流也复用 TRUST_PROXY_HOPS 信任规则。可选环境变量：

| 变量                   | 默认值 | 范围 / 用途                 |
| ---------------------- | ------ | --------------------------- |
| WEATHER_RATE_LIMIT     | 60     | 每访客每分钟天气请求，1–600 |
| CITY_SEARCH_RATE_LIMIT | 20     | 每访客每分钟城市搜索，1–120 |
| WEATHER_CONCURRENCY    | 4      | 天气相关上游并发，1–16      |

上游最多排队 12 个请求、等待 2 秒；供应商限流或连续失败时暂停请求 30 秒。预算拒绝返回 Retry-After。

## 磁贴排序与分组

管理页“磁贴布局”支持最多 12 个内容分组，名称留空时不显示标题；每组独立设置 1–4 列。磁块可通过拖动手柄排序或跨组移动，也可使用上移/下移按钮及“分组”选择器操作。每个磁块可设置 1–4 列宽度，高度始终由内容决定。宽度超过组列数时按组宽显示，平板最多 2 列、手机 1 列。

布局以从左到右、从上到下的顺序排列；高度变化时自动调整占位，保留阅读及键盘顺序。为保持明确顺序，不使用会把后面的磁块提前填入空隙的 dense 重排。移除分组会将其内容移入保留的分组，不会删除磁块；新增内容自动补入首组。空组或全部隐藏的组不会在公开首页显示。

`layout.groups` 保存 `{ id, title, columns, items: [{ id, span }] }`；磁块 ID 使用 `feed-<id>`、`widget-<id>`、`weather`、`bookmarks`、`projects`。旧配置自动生成默认分组。顶部服务入口保持独立，可在“服务入口”中用按钮调整顺序；服务状态仍与入口合并。书签及项目内部条目也可排序。保存后刷新公开首页读取新布局。

## 配置备份与恢复

管理员在管理页底部“配置备份与恢复”下载当前**已保存配置**。文件包含首页内容、分组、跨列宽度、显隐、服务入口和自定义接口配置，不包含当前表单未保存的编辑、`.env`、管理员密码、运行缓存或历史快照。直接写入请求头的令牌属于配置，会随 JSON 导出；环境变量引用保留为引用，迁移时需单独提供对应 `.env`。备份文件未加密，请妥善保存。

恢复支持本应用生成的版本化备份文件，也兼容旧的原始配置 JSON，最大 1 MiB。选择文件后先在服务端校验并展示名称与各类内容数量；这一步不会保存、调用数据源或修改配置。勾选确认并点击恢复后，整份配置会被替换（不做合并），当前未保存编辑将清除。成功后管理页重新加载，公开首页刷新后读取恢复结果。

每次保存修改或恢复前，服务器先把当前已保存配置写入状态文件同目录的 `backups/`，默认即 `data/backups/`，保留最近 10 份配置历史，可检查恢复或下载。快照保存失败会阻止保存或恢复；配置写入失败保留运行中的配置和已创建的快照。Docker 使用现有数据卷持久化这些文件，无需增加挂载。相同配置重复保存不生成历史；管理页“自动配置历史”支持检查恢复或下载，并区分保存前与恢复前记录。

备份读写只对管理员开放，恢复继续校验同源请求和配置 ETag；文件检查后若其他页面已保存修改，恢复会拒绝，需重新检查。当前存储按单进程服务设计，请勿让多个应用实例共享同一状态文件。备份不代替整机或异地备份，迁移仍需保管服务器环境变量。

## 管理页编辑体验

底部固定操作栏显示“有未保存的修改 / 正在保存 / 所有修改已保存”，可随时保存或放弃修改。只有内容、布局或编辑字段真的变化时才标记未保存，预设填写、备份文件选择和预览结果本身不算首页配置修改。离开或刷新有未保存内容的页面时，浏览器会提示；浏览器是否显示提示取决于平台及用户交互条件。草稿只保留在当前页面内存，不写浏览器存储，以免持久化接口密钥。

保存前检查字段，并自动展开、滚动和聚焦第一处错误；JSON 格式、请求头结构、字段路径、时区、必填项及数值范围都有就近提示。服务端仍重新校验全部配置，冲突或请求失败时保留编辑。保存过程中编辑区暂时锁定，避免返回结果覆盖新输入。

自定义磁块支持复制：生成新 ID，深拷贝内容、映射和接口设置，副本紧跟原磁块所在分组、继承宽度及显隐。仍计入最多 20 个磁块。复制前需修正该磁块中的字段错误，不执行上游请求。添加、删除或复制导致表单重绘时，错误 JSON 文本与磁块展开状态会保留；切换模板/数据源按对应编辑上下文保存错误文本。成功保存、明确放弃或恢复备份后重新建立编辑基准。

### 宽度与跨列预览

磁贴布局的“宽度”除 1–4 列外，也支持“整行”。整数宽度超过当前可见列数时自动收缩；“整行”始终铺满所在分组，改变分组列数或屏幕宽度后仍保持铺满。高度仍随内容变化，不增加固定行高设置。

分组上方提供桌面 / 平板 / 手机宽度示意，分别使用分组设定列数、最多 2 列、1 列。隐藏磁块不出现在示意中，点击示意磁块可定位其宽度设置。示意只展示宽度及顺序，不模拟实际内容高度；切换预览不会改变配置或产生未保存标记。

配置项 `layout.groups[].items[].span` 接受 1–4 整数或字符串 `"full"`；已有整数配置保持兼容，复制磁块、备份和恢复沿用该值。保存后刷新公开首页生效。

## 配置更新提示

已打开的公开首页在可见且联网时约每 10 秒检查一次页面版本；返回页面或恢复联网时额外检查，并对短时间重复触发做合并与节流。同一浏览器中，管理页保存或恢复成功会通过 BroadcastChannel 通知首页尽快检查；不支持该能力时仍有定期检查。

配置变化后通过带版本的文档地址读取新布局并重新加载片段，不重载整个页面，保留访客主题及选城偏好。正在磁块内输入或进行键盘操作时暂缓替换，显示“首页配置已更新 / 刷新查看”，之后继续检查；同步失败时可手动刷新。界面资源版本变化会显示“首页已有新版本”。提示与 PWA 的“更新应用”入口、离线提示分别管理。检测失败保持安静，下次继续，不影响磁块数据更新。

`HEAD /page-version` 只返回版本 ETag 与 204/304，无配置正文，使用 no-store，不进入 PWA 缓存。版本标记是随机不透明值，不使用管理员配置摘要；配置内容不变的重复保存不产生新标记。服务重启会重新生成标记，已打开页面会重新同步。此接口不抓取上游，不返回接口地址、字段映射、密钥或管理员配置。

## 项目命名

项目名 Perch，中文名“栖页”，介绍为“安放服务与日常的个人首页”。应用清单、管理页、离线页和图标使用同一标识；首页名称仍可由管理员修改。旧 Kyrie 备份可继续导入，既有主题、选城存储键及跨标签通知频道保留用于兼容，Service Worker 激活时清理旧前缀缓存。应用 id、配置文件路径及数据卷不变，启动入口使用通用 launch.html。

## 数据源诊断

管理页底部展开“数据源诊断”，可查看服务 HTTP 检测、订阅、自定义磁块和默认城市天气的最近尝试/成功/失败时间、处理耗时、连续失败次数及缓存到期。支持按名称、异常或未检查状态筛选。读取列表只看内存记录，不会自动请求上游；点击单个来源“检查”使用当前**已保存配置**，遵循现有缓存。服务入口共享一轮状态检测。手动数据磁块检查字段映射，不访问网络。

错误以固定说明分类为认证、缺少密钥、超时、HTTP 异常、请求受限、响应格式、映射、响应过大、TLS 或网络错误。诊断报告不包含接口 URL、请求头、密钥、原始响应和原始异常。服务检测遇到 401/403 仍表示可达，会注明访问需要认证；API/订阅的 401/403 表示上游认证失败。失败后沿用旧内容和成功获取新数据会分别显示，缓存命中不会刷新最近成功时间。

天气诊断使用独立缓存，只测试管理员配置的默认城市，不检测、记录或展示访客 IP、个人选城、定位接口结果。常规首页天气缓存与访客隔离行为不变。

记录只保存在当前进程内存，重启或保存配置后重新累计，不是持久化历史监控。手动检查需管理员认证、同源 POST，最多全局 2 个不同检查任务、每分钟 30 次；同来源同配置的检查合并。配置改变后旧请求不回填新记录，但仍占并发直到结束，避免因取消共享请求影响首页读者。任务繁忙时请稍后重试。失败结果通常缓存 30 秒；服务检测沿用 60 秒共享缓存。此功能不修改配置、跳过缓存或自动轮询上游。

### 反向代理与配置版本

配置读写及备份恢复预览通过 `X-Config-Version` 返回完整配置版本，不依赖压缩后可能变化的实体 ETag。兼容旧客户端携带的同一完整摘要弱 ETag；配置真正发生变化时仍返回 409，不自动覆盖他人的修改。反向代理应保留 `X-Config-Version` 响应头，管理 JSON 请求使用 no-store。更新服务后需重新打开管理页，旧页面持有的版本不会自动合并。

## 管理工具增强

- **历史差异**：检查历史或上传备份时，显示相对于当前已保存配置的新增、删除、修改和顺序变化。地址、接口认证、映射与原始数据仅提示变化，不展示值；最多列出 100 项。检查不会修改配置，恢复仍需确认和配置版本校验。
- **运行概览**：展开“数据源诊断”，查看当前并发、排队、后台请求、冷却来源，以及进程累计完成、失败和预算拒绝数量。缓存命中/加载计数覆盖 RSS、自定义磁块和聚合服务状态，不包含天气缓存；手动刷新记录时更新，重启清零。
- **字段映射助手**：展开磁块内的助手，读取当前手动数据或 API 的字段结构，选择目标再点选路径。仅返回路径和类型，不显示样本值；常见认证字段被过滤，最多 100 个字段、有限层级，数组只采样首项。支持单值、多值、进度、文本和列表映射。列表条目字段相对于列表项，先设置列表路径，再重新读取。填入后务必通过“测试数据并预览”确认；数值字符串是否有效仍由预览验证。

上游默认全局并发 8、每 origin 并发 2（`UPSTREAM_PER_ORIGIN`）、排队 24、排队等待 2 秒、请求截止 8 秒。可分别通过 `UPSTREAM_CONCURRENCY`、`UPSTREAM_MAX_QUEUE`、`UPSTREAM_QUEUE_WAIT_MS`、`UPSTREAM_TIMEOUT_MS` 调整。诊断和预览使用后台队列：前台请求优先，默认至少留一个全局名额给前台；总并发为 1 时只能串行共享。取消排队会释放队列位置。健康检查只读取响应状态并取消正文；数据读取仍限制 1 MiB。

## CDN 与配置版本

Perch 的正确性不依赖任何 CDN purge 接口，也不需要清除缓存的 Token。动态片段使用 `/fragments/<构建版本>/<公开配置版本>/<模块>`，公开配置版本复用 `/page-version` 的随机标记，与管理配置摘要隔离。旧地址回源时只返回 409 更新提示，不会返回新配置内容；同版本仍会读取不断变化的上游数据，因此这些 URL 不是不可变数据快照。

| 响应                                            | 默认 Cache-Control                                                          |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| 首页、版本文档 `/page/<构建>/<配置版本>`        | `no-store`                                                                  |
| 成功的公开 RSS / 磁块片段                       | `public, max-age=0, s-maxage=60, must-revalidate`，磁块上限不超过其刷新间隔 |
| 成功的服务状态片段                              | `public, max-age=0, s-maxage=15, must-revalidate`                           |
| 天气、城市搜索、失败/过期结果、管理页、版本检查 | `no-store`                                                                  |
| 公开内容哈希静态资源                            | 一年 `immutable`                                                            |

公开片段提供内容 ETag / 304。动态数据的共享 TTL 是源站缓存之外的额外边缘延迟上限，不是保证数据实时；不使用 stale-while-revalidate 延长旧内容可用期。天气即使是固定城市模式也保持不共享，避免手动选城或 IP 位置串用。PWA 不缓存动态文档和片段；PWA 导航优先显示通用启动界面，离线时保留连接反馈与重试入口。

首页默认不启用共享缓存，因为当前构建不跨版本保留静态产物，发布后旧 HTML 可能引用已删除的 JS/CSS。若未来增加静态版本保留与不可变数据快照，才能安全扩大长缓存范围。这里假设代理遵守 HTTP 缓存头且不去掉路径版本；强制“缓存一切”或无视 no-store 的自定义规则需要部署者移除。当前配置存储与公开版本为单进程模型，不支持多副本各自生成版本。

## PWA 启动体验

已安装并完成缓存的 PWA 在进入首页时先显示通用启动界面，无需等待首页网络响应；随后以 no-store 读取最新文档，并行准备样式、入口模块与首批内容；首批内容预取最多等待约 900 毫秒，已就绪磁块直接显示，慢磁块只保留“加载中…”而不再显示第二套骨架。预取成功的磁块跳过首次重复请求。启动界面只包含通用品牌、占位和连接反馈，不缓存站点配置、订阅结果、访客位置或历史页面。首次未受 Service Worker 控制的浏览器访问仍直接获取服务端首页。

进入时优先应用已保存的主题，减少样式加载前的颜色闪烁。慢网或离线保留可用界面，失败可重试，联网后自动连接；“直接打开首页”用于绕过启动壳。应用 id 和 scope 不变，无需重新安装；已有应用需先激活新版本 Service Worker。不同手机系统的原生启动画面仍由系统控制。

## 按上次布局生成启动骨架

首页成功挂载后，浏览器以 `perch-startup-layout-v1` 保存一份结构描述：公开页面版本、保存时间、内容密度、服务数量、分组列数、是否有分组标题、磁块类型、跨列宽度与粗略行数。它不保存名称、模块 ID、网址、接口配置、凭据、天气位置、原始 HTML 或业务数据。

下次 PWA 启动优先用该描述生成占位，沿用首页响应式列数和自然高度布局；仍只显示一层启动骨架，真实首页和首批片段准备好后一次替换。首次访问、缓存无效、超过 30 天或本地存储不可用时，继续使用通用骨架。服务端配置变更后以最新布局为准并更新本地描述；旧布局仅用于短暂占位，不会被当作配置或数据使用。占位行数为估算（最多 8 行），不保证与最终内容完全等高。

## 首屏关键请求链

公开首页、启动和离线入口各自生成独立的小包，避免小型共享 chunk 形成“入口 → chunk → 数据”的串行等待。管理端继续按需拆包，备份和诊断不会提前下载。代价是不同公开入口之间有少量代码重复，优先缩短首次访问的网络依赖链。

极小的主题初始化代码由资源服务嵌入 HTML，响应 CSP 仅加入该固定代码的 SHA-256 哈希，不启用 unsafe-inline，也不拼入任何站点配置。新首页初次加载不再立即查询 page-version；首次常规检查延后约 10 秒，跨标签保存通知、联网及返回页面仍保留强制检查与节流。

这些改动减少串行依赖和阻塞请求，不代表任何网络环境下都能达到固定毫秒数。部署后应在同样的设备、网络节流和缓存条件下重新检查关键链路及 LCP。

首次配置向导仅允许通过本机地址直接访问（例如 `http://127.0.0.1:3210/setup`，远程服务器可使用 SSH 端口转发），不接受反向代理转发的初始化请求。向导和初始化接口同时要求 ADMIN_PASSWORD 管理员认证，写入要求同源 JSON；初始化或管理员首次保存成功后，初始化接口关闭。

## 数据源本地端到端测试

`node --test test/preset-http.test.js` 会启动四个独立的回环 HTTP 模拟服务及一个真实 Perch 实例，用原生 fetch 验证预设、认证头、代理路径前缀、字段映射、预览、配置保存、公开片段与缓存命中。还覆盖错误/缺失密钥、异常实体、空序列、非法 JSON、重定向与公开失败响应，测试结束自动关闭服务并清理临时数据。

浏览器验证可执行 `npm run build` 后运行 `node scripts/preset-lab.mjs`，打开 `http://127.0.0.1:3216/` 或 `/admin`，四个预设及测试凭据已准备好。`PRESET_LAB_PORT` 可指定其他端口，数据全部位于独立临时目录，不读取或改写正式站点配置；该实验服务仅绑定本机并自动注入测试管理员身份。Ctrl+C 关闭全部测试服务并清理状态。

这些服务是按接口结构实现的协议模拟，不是真实产品部署；能验证 Perch 的完整 HTTP 与浏览器链路，但不覆盖实际产品版本、TLS 证书或权限配置差异。

需要真实数据时，运行 `node scripts/preset-lab.mjs --public`，在四个模拟磁块之外增加 PromLabs 公共 Prometheus（`sum(up)`）和 Jellyfin 官方 stable 演示版本磁块，均无需令牌。服务地址来源：[PromLabs](https://demo.promlabs.com/query)、[Jellyfin 官方演示说明](https://jellyfin.org/docs/general/testing/web/)。公共服务仅供低频手动联调，可能停机、限流或升级，不应当作生产数据源。

可选真实网络验证：`PRESET_PUBLIC_TEST=1 node --test test/preset-public.test.js`，通过真实 Perch 管理预览及公开片段验证这两个接口。默认 `npm test` 跳过此测试，CI 不依赖外部服务可用性。Home Assistant 和 Proxmox 的真实认证、权限验证仍需要独立实例。

## 共享连接

管理页“共享连接”统一维护服务基础地址和认证请求头，自定义磁块选择“共享连接”后填写请求路径、查询参数及映射。连接与磁块使用同一个“保存并应用”；预览和字段映射助手读取当前未保存草稿。连接不单独请求上游，使用关联磁块的“测试数据并预览”检查实际接口。

```json
{
  "connections": [
    {
      "id": "home-prometheus",
      "name": "家庭 Prometheus",
      "baseUrl": "https://metrics.example.com/prometheus",
      "headers": { "Authorization": "Bearer ${WIDGET_PROMETHEUS_TOKEN}" }
    }
  ]
}
```

磁块的 `source` 可配置为：

```json
{
  "kind": "connection",
  "connectionId": "home-prometheus",
  "path": "/api/v1/query",
  "query": { "query": "sum(up)" },
  "method": "GET"
}
```

这里的请求地址为 `https://metrics.example.com/prometheus/api/v1/query?query=sum%28up%29`（查询参数由程序编码，等价编码均可）。路径以 `/` 开头，追加到基础地址；不能携带其他域名、查询字符串、片段或目录回退。查询参数最多 30 项，值使用字符串。POST 查询可另设 `body`；认证请求头只能在连接上配置，不允许磁块覆盖。共享连接最多 40 个。

已有独立 API 可在磁块内展开“提取为共享连接”，确认名称和基础路径后转换；磁块 ID、映射和布局保持不变。重复查询参数或无法保留原接口语义的基础路径不会自动转换。常用数据源预设可创建连接或复用已有连接；复制磁块保持同一连接引用。

旧配置缺少 `connections` 时默认为空，原有 API 和手动数据继续使用。有磁块引用的连接不能删除；保存及备份恢复拒绝悬空引用。备份包含连接配置与变量引用，不包含服务器环境变量值；连接差异报告隐藏内容。真实密钥继续放在服务器环境变量中，修改环境变量后需重启服务。

共享的是连接配置，并非原始响应缓存。每个磁块独立请求、映射和缓存；修改连接地址或请求头仅失效关联磁块缓存，重命名连接不清缓存。公开 HTML、片段、诊断和 PWA 缓存不包含连接地址或认证配置。

## 配置体检与诊断导出

展开管理页“数据源诊断”，配置体检会分析**当前已保存配置**和当前进程的已有诊断记录，不读取未保存草稿，不修改配置，也不主动请求上游。检查包括共享连接/独立 API 缺少的密钥环境变量、未引用连接、常见认证信息直接写入配置、手动数据映射错误及尚未填写的服务/订阅地址。可选天气未启用时不作为配置问题。

上游认证、超时、网络、证书、限流、响应格式及字段映射问题来自下方实际“检查”的结果；有效缓存仍可能直接命中，体检不是强制实时连通性检测。每类问题提供处理建议，尚未检查的数据源单独计数，不将“无配置问题”等同于服务在线。认证字段检测基于常见键名，不保证发现所有形式的敏感信息；查询参数及 POST 正文不会展开环境变量。

“重新体检”读取最新记录；“导出脱敏诊断报告”下载 JSON（`format: perch-diagnostics`，`schemaVersion: 1`）。报告包含应用/Node 主版本、来源数量、匿名来源状态、HTTP 状态、尝试及成功失败时间、耗时、固定分类建议和请求预算计数。不包含配置名称、来源 ID、网址、密钥值、环境变量名、原始错误文本、响应正文、访客 IP 或位置。它不是配置备份，也不用于恢复；保留的时间和计数用于排查运行问题。

管理员 GET `/api/admin/config-check` 返回体检结果（管理页可显示缺少的变量名）；GET `/api/admin/diagnostics/export` 返回白名单导出文件。两者均需要管理员认证、使用 no-store，并支持 BASE_PATH 子路径部署。报告只反映当前进程观察，重启后运行记录重新累计。

## RSS 标题筛选与排序

管理页“资讯订阅”中，每个订阅可展开“筛选与排序”：包含/排除关键词支持中文、英文，以逗号或换行分隔，最多各 20 个，每个最多 80 字符。仅匹配标题，按普通文本子串匹配，不区分大小写并规范化全角字符；不执行正则表达式。包含条件可选任一/全部，排除规则优先，空的包含列表不限制文章。

处理顺序为：解析 → 标题筛选 → 排序 → 链接去重 → 显示条数。可保留来源顺序或最新优先，无有效日期的文章排最后；相同日期保持来源顺序。去重仅作用于当前订阅，忽略链接 `#` 片段，保留查询参数；最新优先时保留重复链接中日期最新的一条。没有匹配文章会正常显示空结果提示，不当作上游故障。

旧订阅默认不筛选、保留来源顺序及重复内容。修改规则只失效对应订阅的数据缓存，名称和布局修改保留缓存；规则进入配置备份，但不会下发公开页面。首版不合并多个订阅，不提供跨来源去重、已读状态或正文搜索。

```json
{
  "filters": {
    "include": ["Node", "Vue"],
    "exclude": ["广告"],
    "match": "any",
    "sort": "newest",
    "deduplicate": true
  }
}
```

## 手机展示覆盖

管理页“磁贴布局 → 手机展示覆盖”可启用独立设置。默认继承桌面；启用后在 **520px 及以下**将内容区磁块按独立顺序单列展示，不保留桌面分组标题。可以用上移/下移调整跨分组的阅读顺序、单独隐藏磁块，并为 RSS、链接/列表磁块、书签和项目减少显示条数。顶部服务入口保持原有响应式展示；平板仍沿用桌面布局。

手机条数留空表示继承，只能减少桌面已有条数；桌面条数减少时手机上限会自动收紧，不支持条数的类型会清除对应限制。新增磁块跟随桌面顺序追加，删除磁块时清理手机引用。“恢复继承桌面”清除手机覆盖及无效草稿；只取消启用则保留设置，方便稍后继续。

全局隐藏优先，手机设置不能重新显示全局隐藏模块。手机隐藏仅为展示偏好，不构成访问权限；公开片段仍使用现有权限边界。列表裁剪在展示层完成，共用桌面数据请求与缓存，不额外发起手机专用请求；手机隐藏磁块不参与首次预取和定时加载。窗口跨断点时复用同一份 DOM，恢复桌面分组、顺序与完整条数。

配置保存在 `layout.phone`：`enabled`、`order`、`hidden`、`limits`。备份恢复及配置版本更新沿用现有流程；PWA 启动几何缓存按手机/桌面分别保存，仍不包含标题、接口或业务数据。

## 分组折叠与内外网入口

有名称的内容分组可点击标题或用键盘折叠/展开，默认展开；未命名分组保持原来的无标题展示。状态按分组 ID 和部署子路径保存在访客浏览器，刷新及配置同步后保留，不修改管理员配置。折叠分组跳过启动预取和后续定时加载，展开后立即安排刷新；已在进行的请求可能正常完成。禁用浏览器存储时仍能折叠，但不会记忆。

手机独立展示启用后不显示桌面分组标题，因此使用手机的独立顺序；切回桌面恢复原分组及折叠状态。启动骨架不保存折叠组中的内容占位。

服务入口可选填 `internalUrl`，现有 `url` 作为公网访问地址。存在内网地址时，服务区出现“公网优先 / 内网优先”选择；访客手动选择并在本机记忆，缺少某一侧地址则回退到已有地址。不会自动探测访客局域网，不更改健康检测：检测顺序仍为 `healthUrl` → `url` → `internalUrl`。入口切换只改变浏览器打开的地址，不代表选中网络下的可达性。

内外网访问地址均会进入公开页面，不能在其中填写凭据或将其当作隐藏内部地址的权限机制；独立健康检查地址仍只在服务端使用。备份保留双地址，差异和脱敏诊断报告不展示内网地址。
